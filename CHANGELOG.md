# Changelog

## v0.14.7
- Лицензирование: подпись лицензии Ed25519, реестр поставщика (`license-server/`: выдача, отзыв, восстановление, продление, журнал), состояния active/expiring/expired/revoked/grace/invalid/unlicensed, режимы `off|warn|enforce` и **read-only** при отзыве (вход и просмотр работают, изменения блокируются, после восстановления всё возвращается). Вкладка «Настройки → Обслуживание → Лицензия», права `license.view`/`license.manage`.
- Оффлайн-бандл `scripts/build-offline-bundle.sh` для клиентов без доступа к реестру: `docker save` + `pull_policy: never`, обновление через `scripts/update.sh --offline <бандл>`, версия фиксируется в `.env` только после успешного health-check, авто-откат при ошибке. Бандл публикуется как release-ассет.
- Комплект для внедрения `scripts/build-client-kit.sh` — установка без исходников: Docker из реестра, оффлайн, Kubernetes, нативно (systemd) и web-машина; оффлайн-образы и native-архив в `payload/`, контрольные суммы, гайд `install.md`.
- Установщик `deploy/setup.sh` доводит машину до рабочего состояния сам: ставит Docker Engine + Compose v2, Node.js 20+, PostgreSQL с ролью и базой `helpdesk`; проверяет пароль БД реальным входом до старта сервисов; задаёт `umask 022` и права на релиз, иначе systemd падал с `200/CHDIR`.
- Раздельное развёртывание: режим `-m web` поднимает на второй машине только интерфейс и nginx с TLS, проксирующий `/api` и `/uploads` на API-машину (шаблон `deploy/native/nginx/web.conf.tpl`).
- В сид передаются `ADMIN_EMAIL`/`ADMIN_PASSWORD` из сервисного env: в боевой базе больше не появляется лишний суперадмин `admin@helpdesk.local`; при остатке dev-аккаунта выводится предупреждение.
- «Аптайм» в системной вкладке и в `/api/health` показывает время работы приложения, а не машины.
- Переменные `DEV_LICENSE_*` для dev-стенда, чтобы тестовые лицензии не попадали на прод.

## v0.13.3
- TLS-шлюз: поддержка многохостной установки через `TLS_GATEWAY_MODE=local|remote`.
  - `local` (по умолчанию) — поведение как раньше: API пишет сертификаты в `TLS_CERTS_DIR` и перезагружает nginx через docker.sock.
  - `remote` — шлюз на другой машине: API сохраняет бандл `fullchain.pem`/`privkey.pem`/`meta.json` в `TLS_BUNDLE_DIR`, авто-reload не требуется; бандл скачивается через `GET /api/system/tls/bundle`, применение фиксируется `POST /api/system/tls/remote-applied` (отметка `applied`/`appliedAt`); `reset` удаляет бандл.
- Новые эндпоинты TLS (`tls.manage`): `GET /api/system/tls/bundle` (отдаёт текущие PEM — и для локального, и для внешнего шлюза), `POST /api/system/tls/remote-applied`.
- Изменён ответ `GET /api/system/tls`: поля `deploymentMode`, `location`, для remote — `applied`, `appliedAt`, `bundleDir`.
- Web: карточка TLS показывает бейдж «Локальный/Внешний шлюз»; в remote-режиме — кнопки «Сохранить бандл», «Скачать бандл», «Отметить применённым на шлюзе», «Удалить бандл» и индикатор «ожидает применения / применён на шлюзе».
- Конфигурация (`GET /api/system/config`): блок TLS содержит `deploymentMode` и `bundleDir`; `filesPresent` учитывает режим.
- Исправлена hydration-ошибка `<div>` внутри `<p>`: текстам с бейджами (Режим, Авто-reload, Метод дампа) в карточке конфигурации задан `component="div"`.
- `.env.example`: документированы `TLS_GATEWAY_MODE` и `TLS_BUNDLE_DIR`.
- Версия поднята до 0.13.3.
